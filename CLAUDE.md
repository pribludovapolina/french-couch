# Cahier de français

Сайт с дневным планом изучения французского на октябрь 2026: уроки, упражнения, карточки с интервальным повторением, личный прогресс по логину и паролю. Node.js + Express, база Turso (libSQL), хостинг на бесплатном Render. Деплой, переменные окружения и сброс пароля описаны в [README.md](README.md), здесь они не повторяются.

Тексты интерфейса и комментарии в коде на русском. К ученице обращаемся на «ты» и в женском роде.

## Команды

```bash
npm run dev                      # сервер на http://localhost:3000, база в файле data/cahier.db
python3 content/build_data.py    # пересобрать уроки в public/data/month1.json (нужен openpyxl)
node --check server.js           # проверка синтаксиса; тестов и линтера в проекте нет
```

- Файлы из `public/` сервер читает в память один раз при старте, а `node --watch` следит только за `server.js` и `db.js`. После правки `public/index.html` или пересборки уроков сервер нужно перезапустить вручную.
- Пуш в `main` сразу выкатывается на боевой сайт (`autoDeployTrigger: commit` в `render.yaml`).

## Что где лежит

| Путь | Что это |
|---|---|
| `server.js` | Весь сервер: статика, заголовки безопасности, сессии, API |
| `db.js` | Подключение к базе, схема таблиц, обёртки `get / all / run / tx` |
| `public/index.html` | Весь фронтенд одним файлом: стили, разметка шапки, скрипт. Без сборки и фреймворков |
| `public/data/month1.json` | Уроки. **Генерируется, руками не править** |
| `content/*.py` | Исходники уроков и сборщик |
| `content/plan.xlsx` | Расписание месяца, лист «Месяц 1»: тип дня, минуты, блоки плана |
| `scripts/reset-password.js` | Сброс пароля владельцем |
| `data/`, `_private/`, `.env` | Локальная база, выгрузка личного прогресса, токен. В git не попадают, не коммитить |

## Куда вносить правки

| Задача | Где |
|---|---|
| Текст теории, слова, упражнения, домашка за день | `content/content_days.py` (1–2 окт), `content_w1.py` (5–9), `content_w2.py` (12–16), `content_w3.py` (19–23), `content_w4.py` (26–29), затем пересборка |
| Практикум (трансформации) | `content/drills.py` |
| Вопросы к видео и подкастам | `content/listening_quiz.py`, ключ — id ролика YouTube |
| Вопросы и словарик к Le Petit Prince | `content/reading_quiz.py`, ключ — диапазон глав |
| Ссылки на видео, песни, набор и порядок шагов дня, минуты | `content/build_data.py`: словари `INNER`, `CARTOON` (мультфильмы вместо innerFrench с 14 октября), `SEF`, `SONGS_Q`, `FUN`, `MINUTES`, `ORDER2` |
| Перевод фразы, который показывается после ответа | `content/translations.py`, ключ — фраза из `fr_sentence()` в `build_data.py`; сборщик печатает фразы без перевода |
| Произношение слова русскими буквами | `content/transcr.py`, ключ — поле `fr` слова; сборщик печатает слова без транскрипции |
| Тип дня, общее число минут, блоки плана | `content/plan.xlsx` |
| Перевод слова по нажатию, которого нет в словарях дня | `LEXICON_EXTRA` в `content_days.py` или `forms=[…]` у слова |
| Внешний вид | блок `<style>` в начале `index.html`, цвета — переменные в `:root`; тёмная тема продублирована в двух местах (`prefers-color-scheme` и `data-theme="dark"`), менять оба |
| Как выглядит шаг дня | `STEP_RENDER` в `index.html`, раздел `step renderers` |
| Как выглядит и проверяется упражнение | `renderEx` и `check` в `index.html` |
| Карточки и интервалы повторения | объект `SRS` и раздел `review` в `index.html`: перевод вводом (`checkRu`, `checkFr`), оценка ставится сама; свободная тренировка (`UI.review.free`) расписание не меняет |
| Озвучка, выбор голоса | раздел `speech` в `index.html`: `voiceScore`, `speak` (медленно — кусками по 2–3 слова), выбор голоса — `voicePicker` в панели аккаунта |
| Цвета дней в календаре | `dayBreakdown` и `stepIds` в разделе `plan view` |

Скрипт в `index.html` разбит на разделы комментариями вида `/* ---------------- название ---------------- */`. Искать нужное место быстрее всего по ним:

```bash
grep -n '/\* -----' public/index.html
```

## Как устроен фронтенд

- Один IIFE, DOM строится функцией `el(tag, attrs, ...kids)`. HTML-шаблонов нет.
- `Store` — единственный источник данных: `progress`, `cards`, `texts`, `pasted`, `gloss`. Менять их только через методы `Store` (`setProgress`, `putCard`, `putCards`, `delCard`, `addText`, `putPasted`, `putGloss`): они ставят запись в очередь на отправку и вызывают перерисовку.
- `render()` каждый раз перестраивает весь экран. Он откладывается, пока фокус стоит в поле ввода (`UI.dirty`). Поэтому состояние, которое должно пережить перерисовку, хранится в `UI` (`UI.ex`, `UI.open`, `UI.review`, `UI.drafts`), а не в DOM.
- Маршруты по hash: `#today`, `#plan`, `#cards`, `#d-2026-10-05`.
- Пока человек не вошёл или уроки не загружены, вместо экрана показывается «шлюз» (`renderGate`). Режимы `Store.mode`: `connecting`, `anon`, `db`, `offline`.
- Несохранённое дублируется в `localStorage` (`cahier-pending:<логин>`), черновики текстов — в `cahier-ui`.
- Прогресс уходит целиком с номером версии. При конфликте с другим устройством сервер отвечает 409, и `mergeProgress` делает трёхстороннее слияние.
- Проверка с Claude (`SAMPLE`, `aiReady()`) работала только внутри claude.ai. На этом сайте `aiReady()` всегда ложно, кнопки скрыты, вместо них «Скопировать запрос». Этот код оставлен намеренно, не удалять как мёртвый.

## Как устроен сервер

- API под `/api`: `me`, `register`, `login`, `logout`, `password`, `state`, `progress` (PUT), `items` (POST, пачка `put` и `del`). Ошибки всегда в виде `{ error: 'код' }`, текст для человека подбирает фронтенд.
- Изменяющие запросы требуют заголовок `X-Cahier: 1` и совпадение `Origin` с хостом. Функция `api()` на фронтенде ставит заголовок сама.
- `/data/*` отдаётся только вошедшим.
- Сессия — cookie `cahier_sid`, в базе лежит только её sha256.
- CSP задана в `server.js`. Скрипты разрешены только свои и с cdnjs, шрифты — Google Fonts, `connect-src 'self'`. Подключая любой новый внешний ресурс, нужно дописать его домен в CSP, иначе браузер молча его заблокирует.

## Данные

Таблица `progress`, один JSON на человека:

```
{ days: { "2026-10-05": { steps: { theory: <время отметки>, … }, ex: { e1: "ok" | "almost" | "wrong", … }, tcf: "…" } } }
```

Таблица `items`, поле `coll`: `cards` (карточки), `texts` (домашки с отзывами), `pasted` (вставленные тексты песен и глав), `gloss` (сохранённые переводы слов).

День в `month1.json`: `date, type, minutes, plan, steps[], ready, topic, theory, vocab, topics, exercises, homework, drill, fun`. Шаг: `{ kind, title, min, … }`. Схемы уроков описаны в начале `content/content_days.py`, конструкторы упражнений — в `content/h.py`.

## Подводные камни

- **Идентификаторы — это ключи чужого прогресса.** Упражнения получают `e1…eN` по порядку в `ex(...)`, практикум — `D-n`, вопросы — `L<i>-<n>` и `R-n`. Если вставить или удалить упражнение в середине уже опубликованного дня, сохранённые ответы съедут на соседние задания. Новое добавлять в конец списка. `id` слова (`w-…`) и темы — это id карточки: при переименовании у всех, кто уже добавил слово, появится дубль.
- Шаг отмечается по `kind`, поэтому в одном дне может быть только один шаг каждого вида.
- После правок в `content/` коммитить и исходник, и пересобранный `month1.json`. Сборка детерминированная: без правок она даёт файл байт в байт как в репозитории. В конце сборщик печатает дубли id и сверку минут — их нужно просмотреть.
- Новый тип упражнения — это три места: конструктор в `content/h.py`, ветка в `renderEx`, подпись в `EX_LABEL`.
- Новый вид шага — `STEP_RENDER` в `index.html` плюс `ORDER` и `ORDER2` в `build_data.py`, иначе сборка упадёт на сортировке.
- Новый раздел личных данных — `COLLS` и ответ `/api/state` в `server.js`, поля `Store`, а также `load`, `reset`, `exportData`, `importData`.
- Правило для логина записано дважды: `LOGIN_RE` в `server.js` и регулярка в `renderAuth`. Параметры scrypt — в `server.js` и в `scripts/reset-password.js`.
- Таблицы создаются через `CREATE TABLE IF NOT EXISTS`, миграций нет. Изменение существующей таблицы само на боевую базу не попадёт: нужен отдельный `ALTER TABLE`.
- Без `TURSO_DATABASE_URL` в продакшене сервер намеренно отказывается работать с файлом. Это защита от потери аккаунтов на Render, не обходить.
- Месяц зашит в нескольких местах. Для второго месяца править: имя файла `month1.json` в `loadData`, «из 31» в `renderDay`, «Октябрь 2026» и «80,8 ч» в `renderPlan`, «из 30» в запросе домашки; в `build_data.py` — лист «Месяц 1», диапазон строк `range(2, 33)`, даты `start` и `end`, особые дни `2026-10-30` и `MINUTES`.
- `FILM` в `reading_quiz.py` сейчас нигде не используется.
